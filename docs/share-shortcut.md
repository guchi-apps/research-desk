# 共有メニュー・ショートカットからワークリレーへ送る（#144）

他のアプリから、写真や記事をワークリレーへ渡す方法をまとめる。

| 端末 | 方法 | 写真 | 記事（URL） |
|---|---|---|---|
| iPhone | ショートカットアプリ | 「ワークリレーへ写真」 | 「ワークリレーへ記事」 |
| Android | ホーム画面に追加したアプリ | 共有メニューの「ワークリレー」 | 共有メニューの「ワークリレー」 |

**iPhoneのホーム画面アプリは、共有メニューに出ない。** SafariがWeb Share Targetに対応していない
ためで、iOS 26でも同じ（2026-09時点）。そのため、ショートカットから同じ受け口
（`POST /api/share/inbox`）を呼ぶ。

**ショートカットの「URLを開く」は、ホーム画面アプリではなく必ずSafariで開く。**
iPhoneではSafariとホーム画面アプリでログイン状態が別々なので、**Safariでも一度
https://research-desk.gucchii.com/ にログインしておく**。

## 事前に用意するもの

- **ショートカット用のトークン**：1Passwordの`op://apps/research-desk/share-shortcut-token`にある。
  本番の`.env`の`SHARE_SHORTCUT_TOKEN`と同じ値。未設定の場合、受け口は503を返す
- **Safariでのログイン**：上記のとおり、Safariでもログインしておく

## ショートカット1：「ワークリレーへ写真」

写真アプリなどで写真を選んで共有すると、Safariで「画像を送る」画面が写真入りで開く。
1回で20枚・合計10MBまで。

ショートカットアプリで「＋」から新規作成し、次のアクションを上から順に置く。
アクション名はiOSのバージョンによって少し違うことがある。

1. **ショートカットの詳細を設定する**
   - 画面下の「ⓘ」を開き、「共有シートに表示」をオンにする
   - 先頭に「**共有シート**から**画像**を受け取る」が出るので、受け取る種類を「画像」だけにする
   - 「入力がない場合」は「停止」のままでよい
2. **画像を変換**：「ショートカットの入力」を「JPEG」に変換する
   - 「詳細を表示」から、画質を 0.8 程度にし、「メタデータを保持」をオフにする（撮影場所を送らないため）
3. **画像のサイズを変更**：「変換済みの画像」を「**最長辺**」「1600」に変更する
   - 1枚あたりおよそ300〜600KBに収まり、20枚でも10MBを超えにくい
4. （任意）**入力を要求**：「テキスト」で、プロンプトを「写真タイトル」にする
   - 空のまま進めてもよい。その場合は「画像を送る」画面でタイトルを入力する
5. **URLの内容を取得**
   - URL：`https://research-desk.gucchii.com/api/share/inbox`
   - 「詳細を表示」を開き、次のとおり設定する
     - 方法：`POST`
     - ヘッダ：キー `Authorization`、値 `Bearer <トークン>`（`Bearer`と半角スペースの後にトークン）
     - 本文を要求：`フォーム`
       - フィールドを追加 →「ファイル」：キー `files`、値「サイズ変更後の画像」
       - （4.を置いた場合）フィールドを追加 →「テキスト」：キー `title`、値「入力されたテキスト」
6. **辞書の値を取得**：「URLの内容」から、キー `openUrl` の値を取得する
7. **URLを開く**：「辞書の値」を開く

名前を「ワークリレーへ写真」にして保存する。

### 使い方

写真アプリで写真を選ぶ（複数枚を選ぶときは「選択」から）→「共有」→「ワークリレーへ写真」。
Safariで「画像を送る」が開き、「共有から写真をN枚受け取りました」と表示される。

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 6.で値が空になり、何も開かない | 受け口がエラーを返している。5.の直後に「クイックルック」を一時的に置くと、`message`に理由が出る |
| `unauthorized` | 5.のヘッダのトークンが違う。`Bearer `の後ろの値を確認する |
| `share_shortcut_not_configured` | 本番の`.env`に`SHARE_SHORTCUT_TOKEN`が入っていない |
| `too_large` | 合計10MBを超えた。3.の「最長辺」を小さくするか、枚数を減らす |
| ログイン画面が開く | Safari側でログインしていない。ログインして10分以内に「画像を送る」を開けば、残っている写真を読み込む |
| 「共有された写真が見つかりませんでした」 | 受け取りから10分以上経ったか、すでに読み込み済み。もう一度共有する |
| 1枚しか届かない | 5.のファイルフィールドのキーを`files[]`にしてみる（受け口はどちらのキーも受け付ける） |

## ショートカット2：「ワークリレーへ記事」

Safariやニュースアプリで記事を共有すると、Safariで「共有された記事」画面が開く。
事業を選んで「新着記事に追加する」を押す。トークンは要らない。

1. 「ⓘ」で「共有シートに表示」をオンにし、受け取る種類を「**URL**」「**Safariのwebページ**」「**テキスト**」にする
2. **URLエンコード**：「ショートカットの入力」をエンコードする
3. **テキスト**：`https://research-desk.gucchii.com/dashboard/share?url=` の直後に「URLエンコード済みテキスト」を差し込む
4. **URLを開く**：「テキスト」を開く

受け取ったのがURLではなく文章だった場合も、文章の中にURLがあればそれを記事として扱う。
URLの無い文章（メモ等）は、件名を確認して社用メールへそのまま送れる（#149）。

## 写真の置き場所（#64との関係）

写真はワークリレーのサーバーの**メモリにだけ**置き、ディスクにもDBにも書かない。
「画像を送る」画面が受け取った時点か、受け取りから10分経った時点で消す。
サーバーが再起動しても消える。詳しくは`docs/architecture.md`の「共有メニュー・ショートカットからの受け取り（#144）」を参照。
